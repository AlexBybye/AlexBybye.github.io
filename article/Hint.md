## AST Diff 语义层复查机制
高大上一点是"结构约束下的可控生成"，从"生成后验证"到"生成中校验"，构建端到端可验证的 Text-to-SQL 系统
# 一、问题背景

当前 Text-to-SQL 生成流水线分为三阶段：

- **Stage1**：意图接地（Grounding）
- **Stage2**：SQL 骨架生成（Sketch）→ 仅做**语法 / 引用静态检查**
- **Stage3**：参数填充 + 强化学习（RL）→ 执行后验证

### 核心痛点

静态检查只能保证**语法合法、可执行**，但无法保证**符合用户真实意图、结构正确**。

错误在**执行后才被发现**，导致 Stage3 大量**无效 RL 探索**，浪费算力、降低收敛速度、影响最终准确率。

---

# 二、核心创新

**从「语法合法」升级为「意图匹配」**

提出 **AST Diff 语义层复查机制**：

基于轻量级自然语言意图库，生成**预期 AST 骨架**，与模型输出的 Sketch 做**结构化 Diff**，在 Stage2 生成后**立即做语义前置校验**。

---

# 三、技术方案（流程图）

```plain
自然语言 ──→ 意图库匹配 ──→ 预期 AST 骨架
                              ↓
Stage2 生成 Sketch ──→ 【AST Diff 对比】
                              ↓
                    ├─ 一致 → 进入 Stage3
                    └─ 偏差 → 差异定位 → 修正返工
```

# 四、轻量级意图库构建（KBC 式自动挖掘）


**优势**：自动挖掘 + 极低成本人工，不依赖专家规则。

# 五、与现有静态检查对比

表格

|维度|传统静态检查|AST Diff 语义复查|
|:--|:--|:--|
|校验时机|Stage2 生成后|Stage2 生成后（即时）|
|校验标准|通用语法规则|**意图库预期 AST 结构**|
|语义理解|❌ 无|✅ 匹配用户真实意图|
|错误定位|语法违规点|**精准差异 AST 节点**|
|修正策略|通用提示|**基于差异类型的精准返工**|
|执行成本|无（静态）|无（静态结构对比，零执行成本）|
# 六、与相关工作对比（SQLens / KBC）

## 1. 三方案横向对比

表格

| 维度     | SQLens   | KBC 论文      | 本方案                 |
| :----- | :------- | :---------- | :------------------ |
| 核心目标   | 执行后纠错    | 离线知识库构建     | **生成时语义校验**         |
| 错误发现时机 | 执行后（运行时） | 离线构建时       | **生成时（编译时）**        |
| 校验方式   | 执行结果反馈   | Schema 关联挖掘 | **AST Diff 结构对比**   |
| 中间表示   | 无显式 IR   | 知识图谱        | **Sketch（可执行 IR）**  |
| 流水线位置  | 外接纠错模块   | 数据预处理       | **嵌入 Stage2 训练流水线** |
| 可解释性   | 错误类型分类   | 知识关联可视化     | **差异节点精准定位**        |
## 2. 核心区别一句话

- **vs SQLens**：SQLens 是**执行后看病**，本方案是**生成前体检**，提前拦截错误。
- **vs KBC**：KBC 是**离线挖知识**，本方案是**在线用知识**，直接约束生成结构。

## 3. 架构差异

- **SQLens**：生成 → 执行 → 报错 → 重生成（循环执行，成本高）
- **KBC**：离线挖掘 → 构建知识库 → 辅助模型（不参与生成校验）
- **本方案**：意图库 → 预期 AST → AST Diff → 修正 → 进入 Stage3
    
    **嵌入 Stage2，生成时即时校验，零执行成本**
    
# 七、创新点提炼

## 三大核心创新：**前置化 + 结构化 + 流水线嵌入**

1. **验证前置化**：把错误拦截从执行后提前到 Sketch 生成时，杜绝无效 RL 探索
2. **校验结构化**：用 AST Diff 做结构级对比，实现意图级语义校验
3. **流水线嵌入**：无缝融入 Stage2，不破坏原有训练闭环

**独特优势**：

**零执行成本、极低成本构建意图库、可解释性强、大幅提升 Sketch 正确率**。

意图库构建不是额外成本吗？
自动挖掘 + 2 小时人工，远低于执行验证与 RL 无效探索的开销。

###  与 RL 训练的结合点-嵌入流水线

```plain
Stage2 训练流程（加 Diff 复查后）：

Epoch 1-N: 冻结 Diff 模块，纯 SFT 训练 Sketch 生成
           ↓
Epoch N+1: 开放 Diff 复查，错误样本 → 修正后重入训练
           ↓
Reward 设计：Sketch 一次通过 Diff 得 +1，返工修正后通过得 +0.5
           ↓
形成闭环：生成 → Diff → 修正 → 强化"结构正确"偏好
```

**报告一句话**：Diff 复查不仅是推理时校验，更是训练时数据筛选与奖励信号来源。
