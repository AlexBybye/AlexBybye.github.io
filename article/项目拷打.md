### 1. VPet 桌宠 MOD

#### 核心架构设计：三层模型

- **数据模型层 (`ModInfo.cs`)**: 负责“怎么解析”。它是一个轻型 DTO-数据传输对象，只保存 MOD 的基础属性（名称、作者、路径、标签）。
内部集成了对 `info.lps` 的解析逻辑和基于子文件夹名称的自动标签识别，这里在modinfo构造函数中做了个异常捕捉防止因为坏mod导致lps解析失败。

- **逻辑调度层 (`MODManager.cs`)**: 负责“怎么取数据”。异步并发是在ListModAsync中，没有直接读取文件，
先是进行一个防抖，1.5s内如果有上次刷新操作，则直接返回缓存的cacheMods。强缓存机制，确保只要磁盘内容没变，就只读内存。
超过时间为了防止C#并行冲突的读磁盘，先申请信号量锁，使用 `_semaphore = new SemaphoreSlim(1, 1)`进行信号量隔离，不用lock锁因为会造成线程拥塞。
**双重检查 (Double-Check)**:
    在进入信号量前检查一次时间（初筛）。
    在获取信号量后再次检查时间（确保在排队等待期间，没有其他线程刚完成刷新）。
 通过task.run，一个类似于web worker的方式，这个和JavaScript的事件循环思想很像，就是开启了一个类似 **Web Worker** 的线程，调用modinfo，把任务给到了线程池。 但由于，为了防止多个 UI 动作同时触发扫描导致竞争， 它处理缓存、防抖、异步扫描和多源（本地+Steam）合并。
此外也是在这个抽象层统一扫描逻辑，把本地和steam工坊的mod基础属性集中。
    
- **UI 交互层 (`MainWindow.xaml.cs`)**: 负责“怎么展示”。它不参与业务逻辑，只负责通过异步回调获取数据并更新界面。

### 2. 个人博客 
#### 自动化脚本如何实现：
第一步：目录扫描
脚本首先利用 Node.js 的 fs.readdirSync 扫描 public/album 目录，利用正则表达式（`.jpg|.png|.webp` 等）过滤出图片
第二步：元数据解析——学习hexo-anzhiyu的处理方法
Front Matter 提取：通过搜索 --- 分隔符，将 Markdown 文件头部的 YAML 块切分出来。
高性能都做了什么？
利用浏览器原生 API `IntersectionObserver` 监听图片 DOM 节点。当节点与视口交叉（isIntersecting）时，将真正的地址赋值给 `src`
#### 性能优化有哪些？
1. **相册功能** 
    - **虚拟滚动**: 使用 Canvas 物理引擎模拟图片的动态布局
    - **图片懒加载**: 使用 `loading="lazy"` 属性优化加载性能
    - **动画效果**: requestAnimationFrame 实现的 60FPS 流畅动画
    - **Canvas 物理引擎**: 图片带有物理运动效果，模拟真实世界的碰撞反弹
2. **文章系统** 
    - **按需加载**: 只在访问时加载特定文章内容
    - **智能缓存**: 利用 localStorage 缓存点赞和评论数据
    - **Markdown 渲染**: 使用 marked 库实现服务器端渲染
3. **音乐播放器**
    - **响应式设计**: 基于 Pinia 的全局状态管理
    - **音频控制**: 支持播放、暂停、上一首、下一首等功能
    - **分类浏览**: 按音乐类型过滤和展示

### 1. useRequest Hook - 异步请求管理
### 设计理念
在现代前端应用中，异步请求是最常见的操作之一，但手动管理loading、error、data状态非常繁琐。useRequest Hook旨在提供一个统一的请求管理解决方案。
### 面试要点讲解：

**问题场景**：在实际开发中，我们经常需要处理API请求的loading状态、错误处理、数据回填等，每个组件都要重复写相同的逻辑。
### 2. useStorage Hook - 响应式本地存储
### 设计理念
localStorage/sessionStorage是客户端数据持久化的重要方式，但原生API缺乏响应式特性。useStorage Hook将本地存储与Vue的响应式系统结合，实现数据的双向绑定。
### 面试要点讲解：
**问题场景**：需要在多个组件间共享数据，并且要求刷新页面后数据仍然存在，同时还需要响应式更新。
1. **为什么需要序列化/反序列化**？答：localStorage只能存储字符串，需要处理复杂数据类型
2. **跨标签页同步如何实现**？答：利用storage事件监听其他标签页的存储变化

### 1. 电商页面白屏 / 卡顿 / 接口超时，怎么快速定位？
1. **白屏优先看控制台**
    - 打开 F12，先看 **Console 报错**：资源加载失败、JS 执行异常、路由报错、跨域、图片 / 字体 404。
    - 看 **Elements**：根节点是否渲染、#app 是否为空、是否被 CSS 隐藏。
    - 看 **Source**：是否构建产物缺失、chunk 加载失败、路由懒加载出错。
2. **卡顿优先看性能面板**
    - 打开 **Performance** 录制，看长任务、重排重绘、内存暴涨。
    - 看 **ECharts / 列表**：是否未做虚拟滚动、未做防抖节流、大数据直接渲染。
    - 看 **WebWorker / 主线程阻塞**：我项目里 MOD 加载、图片处理都用异步避免阻塞。
3. **接口超时优先看网络面板**
    - 看 **Network**：状态码、超时时间、请求头、参数、跨域、重试次数。
    - 排查：接口本身慢、参数错误、网关超时、后端限流、WebSocket 断线。
    - 前端处理：**Axios 超时设置、错误重试、请求拦截、缓存、降级展示**。
4. **快速复现 + 定位根因**
    - 区分：开发环境 / 生产环境、本地 / 部署、首次加载 / 热更新。
    - 用 **SourceMap + 错误日志 + 监控** 快速定位到文件与行号。
