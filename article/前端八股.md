一、Vue3 Proxy 如何处理数组 + ref /reactive 底层区别
1. Vue3 Proxy 如何处理数组
Vue3 不再像 Vue2 那样重写数组 7 个方法（push/pop/shift/unshift/splice/sort/reverse）。
Proxy 可以直接监听数组的索引修改、length 修改、数组新增 / 删除。
能监听：
arr[index] = xxx
arr.length = 0
arr.push(xxx)
底层原理：
Proxy 拦截 get/set/deleteProperty/has 等操作。
数组也是对象，Proxy 天然支持，不需要特殊 hack。
2. ref 和 reactive 底层区别
reactive
只能对引用类型使用（对象 / 数组 / Map/Set）。
底层是 Proxy 代理整个对象。
解构 / 展开会丢失响应式。
内部自动依赖收集 + 触发更新。
ref
支持基本类型 + 引用类型。
底层是 class 封装，通过 get value / set value 做响应式。
基本类型：靠 value 劫持。
对象类型：内部会自动交给 reactive 处理。
解构 / 赋值不会丢失响应式。
JS 中必须 .value，模板中自动解包。
一句话总结
reactive = Proxy 代理对象
ref = 类封装 + value 劫持（对象自动转 reactive）
`ref` `` JS 里修改必须加 value `` 
`reactive` `` 直接解构会丢失响应式 一般实战全用ref，但显然后者proxy更高效。vue3习惯性把所有响应式数据都放到state中集中管理，并用reactive来初始化state使性能高效reactive自带拆包属性，所以只要外边有reactive，里面的ref搞出来不用 .value``
`toRefs```把 reactive对象转成 ref，防止解构丢失， 实战一般用storeToRefs ，因为和pinia接轨，收取state``

#### 计算机网络
从输入URL到页面加载完成的整个过程

1. **URL解析和DNS查询**
    浏览器解析URL结构
    系统DNS缓存查询后向DNS服务器发起递归查询
    `` 如果本地缓存都没有命中，浏览器会向本地DNS服务器（通常由ISP提供或手动配置）发起递归查询请求。本地DNS服务器会逐级向上（根域名服务器 -> 顶级域名服务器 -> 权威域名服务器）查询，直到获取到目标域名对应的IP地址 ``
2. **TCP连接建立**
    三次握手建立TCP连接 `` 
第一次握手（客户端 → 服务端
    客户端发：`SYN`
    意思：我能发消息，你能收到吗？
第二次握手（服务端 → 客户端）
    服务端回：`SYN + ACK`
    意思：我收到了，我也能发，你能收到吗？
第三次握手（客户端 → 服务端
    客户端发：`ACK`
    意思：我也收到你的消息了，连接建立，可以传输数据。 ``
    如果是HTTPS还需要TLS握手
    `` 
    TLS 握手 = 协商加密方式 + 验证身份 + 安全交换密钥
    非对称加密：传对称密钥
    对称加密：实际加密传输数据 ``
    `` 
    重传：
    超时重传：超过 RTO 时间没收到 ACK，重发。
    快速重传：收到 3 个重复 ACK，不等超时直接重传。依靠序列号 + 确认号实现 ``
3. **HTTP请求和响应**
    浏览器发送HTTP请求
    服务器处理请求并返回响应
    浏览器接收响应数据
4. **页面渲染过程**
    HTML解析构建DOM树
    CSS解析构建CSSOM树
    合并DOM和CSSOM生成渲染树（Render Tree）
    布局计算&页面绘制

http2.0 相对于 http1.0 有哪些优化
多路复用：在一个 TCP 连接上同时发送多个请求和响应，解决队头阻塞。
二进制分帧：将 HTTP 消息分割成多个帧。
头部压缩：用 HPACK 算法对 HTTP 头部进行压缩。
服务器推送：支持服务器主动向客户端推送资源，减少请求次数。

##### 浏览器缓存
将用户访问过的页面资源存储在本地，当用户再次访问同一资源时，直接从本地加载。在此之前，要ServiceWorker能拦截所有请求，自己决定走缓存还是网络，存放cache
主要分为两大类：强缓存和协商缓存。
在加载资源时，优先判断强缓存。强缓存的实现依赖于 HTTP 响应头中的两个字段：`Expires`绝对时间 和 `Cache-Control`相对时间
如果强缓存未命中或过期，则进行协商缓存。两种方式：
`Etag`/`If-None-match` 资源未发生变化，返回 `304 Not Modified` 继续使用本地缓存；已变化返回新的资源和 `200 OK` 。
**`Last-Modified` / `If-Modified-Since`** 修改时间判断
CDN`` 分布在全球的"缓存服务器"，让用户就近访问 ``：解析DNS，就近访问，返回用户最近的 CDN 节点 IP ，之后在分站进行`Expires`等，可以存静态资源

#### 性能优化
##### 一、网络层优化（最常考）
1. **资源压缩合并**
    - JS/CSS/HTML 压缩（去掉空格、注释、缩短变量名）
    - 合并文件减少 HTTP 请求数
    - 服务端开启 **Gzip / Brotli** 压缩（体积可减少 60%~80%）
2. **浏览器缓存（必考）**
    - **强缓存**：`Cache-Control`、`Expires`，直接读本地，不发请求
    - **协商缓存**：`ETag / If-None-Match`、`Last-Modified / If-Modified-Since`，发请求验证是否更新
    - 静态资源加 **hash 文件名**，实现永久缓存
3. **CDN 加速**
    - 静态资源（JS/CSS/ 图片 / 字体）放到 CDN
    - 就近节点访问，降低延迟、分担源站压力
4. **DNS & 连接优化**
    - `dns-prefetch`：提前解析域名
    - `preconnect`：提前建立 TCP + TLS 连接
    - 减少域名数量，降低 DNS 查询开销
5. **HTTP 版本升级**
    - HTTP/2：多路复用、头部压缩、并行传输
    - HTTP/3：基于 UDP，更快更稳
6. **预加载策略**
    - **preload**：加载当前页面**关键资源**（字体、核心 CSS）
    - **prefetch**：空闲加载**未来可能用到**的资源（下一页）
    - **prerender**：直接预渲染整个页面
##### 二、资源加载优化（首屏核心）
1. **懒加载（按需加载）**
    - 路由懒加载：`() => import('./Home')`
    - 组件懒加载：动态 import
    - 图片懒加载：`loading="lazy"` 或 IntersectionObserver
    - 目的：**减小首屏体积，加快首屏渲染**
2. **代码分割 Code Splitting**
    - 按路由 / 组件 / 第三方库分割
    - 避免单文件过大
    - 利用 webpack/vite 自动拆包
3. **图片优化（高频）**
    - 使用 **WebP/AVIF** 格式（体积小、画质好）
    - 响应式图片：`srcset` + `sizes`，根据屏幕加载不同尺寸
    - 图片压缩、小图转 base64、雪碧图（CSS Sprite）
    - 图片懒加载、避免布局偏移（给 img 固定宽高）
4. **静态资源优化**
    - 字体压缩、使用 `font-display: swap`
    - 第三方脚本异步加载
##### 三、渲染层优化（重中之重）
1. **减少重排（Reflow）重绘（Repaint）**
    - 重排：修改布局（宽高、位置、display）→ 成本最高
    - 重绘：修改颜色、背景 → 不触发布局
    - **优化方法**
        - 批量操作 DOM（先隐藏再修改）
        - 使用 **transform / opacity** 做动画（触发 GPU 加速，不重排）
        - 避免读取 offset 等属性导致布局抖动
        - 开启 `will-change` 提前告诉浏览器优化
2. **CSS 优化**
    - CSS 放 **head**，防止无样式闪烁（FOUC）
    - 避免 `@import`（阻塞、串行加载）
    - 降低选择器嵌套，提升解析速度
    - 减少通用选择器、属性选择器
3. **JS 阻塞优化**
    - JS 放底部
    - 使用 `defer` / `async` 异步加载
        - `defer`：HTML 解析完执行，**保持顺序**
        - `async`：下载完立即执行，**不保证顺序**
    - 避免长任务阻塞主线程
4. **长列表优化**
    - **虚拟滚动（虚拟列表）**：只渲染视口内元素
    - 下拉分页加载，避免一次性渲染大量 DOM
##### 四、代码执行优化
1. **减少 DOM 操作**
    - DOM 操作非常耗性能，尽量缓存 DOM 对象
    - 批量修改，使用 DocumentFragment
    - 虚拟DOM，JS来搞
2. **事件优化**
    - **事件委托**：利用冒泡，给父元素绑定一个事件
    - 防抖（debounce）、节流（throttle）：scroll/resize/input
3. **Web Workers**
    - 把计算密集型任务丢到 Worker，不阻塞主线程
4. **避免内存泄漏**
    - 及时清理定时器、事件监听
    - 避免意外的全局变量
    - 闭包慎用
5. FCP（First Contentful Paint）首次内容绘制
定义：页面第一个文本 / 图片绘制的时间。
优化：
减少首屏资源体积
关键 CSS 内联
避免渲染阻塞 JS
6. LCP（Largest Contentful Paint）最大内容绘制（核心指标）
定义：页面最大块元素渲染完成时间。
优化核心：
加快图片加载（WebP、CDN、宽高比、预加载）
减少服务端响应时间 TTFL
避免大尺寸阻塞资源
7. CLS（Cumulative Layout Shift）布局偏移（体验核心）
定义：页面没有用户交互却发生抖动。
优化：
图片 / 视频固定宽高比（aspect-ratio）
不动态插入元素顶开布局
字体不抖动（font-display:swap）
8. FID（First Input Delay）首次输入延迟
定义：用户第一次交互到浏览器响应的延迟。
优化：
减少长任务
拆分 JS、防抖节流
Web Workers 处理计算
9. TTI（Time to Interactive）可交互时间
定义：页面稳定可交互的时间。
优化：
代码分割
懒加载非关键组件
压缩资源 + 缓存
#### 前端安全
SSL/TLS：
- **对称加密**：速度快，用于传输真实数据
- **非对称加密**：速度慢，只用来**安全交换对称密钥**
前端权限控制（路由守卫 + 按钮级 + RBAC）
1. 路由权限（最常用）
思路：前端路由表 + 用户角色 + 过滤生成可访问路由
实现：
路由配置 meta: { role: ['admin'] }
全局路由守卫 beforeEach
获取用户角色 → 过滤路由 → addRoute 动态添加
2. 按钮级权限（细粒度）
实现：
自定义指令 v-permission="add_user"
全局方法 $auth('add_user')
组件内判断权限显隐按钮
原理：
用户权限列表（数组 / Map）
检查当前按钮标识是否存在
3. RBAC 模型（面试必说）
Role-Based Access Control 基于角色的权限控制。
三要素：
用户 User
角色 Role（admin/editor/guest）
权限 Permission（user:add、user:del、article:edit）
关系：
用户 ← 一对多 → 角色
角色 ← 一对多 → 权限
优点：
易维护、易扩展、权限统一管理

#### 工程化
vite和webpack区别：
1：打包treeshaking
`` 目的：打包时冗余代码不打包 ``
优化：Webpack 需要配置，Vite 开箱即用
2：热更新HMR比webpack快
**WebSocket 通信**：Vite 通过 WebSocket 与客户端建立通信，当文件发生变化时，服务器会通过 WebSocket 向客户端发送更新信息。
**增量更新**：Vite 只会更新发生变化的模块，而不是重新打包整个项目，进一步提高了更新速度。
**原生 ES 模块**：Vite 使用 ESM 进行代码加载，避免了 Webpack 的打包和模块解析过程，大大提高了加载速度。
3：按需编译：只编译请求的文件，用`esbuild`预构建依赖

CSS代码优化大法：
SASS：美观化，个人感觉和Eslint差不多
Postcss：这个插件融合了许多实用的，比如css压缩 treeshaking等
