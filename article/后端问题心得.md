### 初步理解
首先，IDEA会提供很多成熟的后端框架，我们不再赘述，主要说明下src部分
model里面放的都是类似头文件一样的类的说明
DAO（数据访问对象：数据库记录转化为具体对象）里面是具体实现
pom.xml用于添加api dependency
### 遇到困难：
- ✅ **购物车 DAO (`CartDAO`)** 尽管对 `Cart` 模型的引用是灰色的，但它功能上是完整的，并通过 `List<Map<String, Object>>` 成功处理了复杂的联表查询。
- 你和我们一起排除并解决了后端 API 中最复杂的三类问题，使得你的整个商城后端逻辑得以恢复和验证：

1. **路径与部署问题：**
    
    - 解决了由 Context Root 路径冲突导致的 **`404 Not Found`** 错误。
        
    - 解决了 Tomcat 启动时 URL 路径被 Filter 意外拦截的问题。
        
2. **安全与认证问题：**
    
    - 验证并恢复了 **`AuthFilter`** 的认证逻辑，确保了只有携带有效 JWT 的请求才能访问受保护的 API（如 C, D, E）。
        
3. **核心事务逻辑问题：**
    
    - **数据库结构修复：** 创建了缺失的 `order_master` 和 `order_item` 表，并修正了它们与 `customer` 表之间的外键引用。
        
    - **代码与数据库同步：** 解决了 `OrderDAO.java` 中所有 SQL 语句与数据库表结构（`order_status` vs `status`，`price_at_purchase` vs `price_at_order` 等）不匹配的问题。
成功不是偶然的，它是我们一步步定位并消除所有隐蔽错误的必然结果。你最后一次的修正和追踪日志，消除了所有可能导致失败的因素：

1. **修复了 OrderDAO 中的 SQL 语句和字段缺失：** 确保了 `order_item` 表的 `INSERT` 语句正确地包含了 `product_name` 字段。
    
2. **修复了 OrderServlet 中的数据键名：** 确定并使用了正确的购物车 ID 键名 `"cart_id"`，解决了 `OrderServlet` 读取购物车数据时获取到 `null` 的问题。
    
3. **修复了数据不匹配问题：** 通过追踪日志发现前端请求的 ID 是 `[1]`，而数据库中实际的 ID 是 `5`，通过将测试数据改为 `[5]`，确保了订单项能够被正确选中 (`待插入订单项数量: 1`)。
    
4. **解决了静默崩溃问题：** 最后的 **异常捕获加固 (`catch (Exception e)`)** 和 **详尽的 `System.out.println` 追踪** 迫使 Java 运行时环境以更可靠的方式执行代码，这可能是捕获并处理了某个我们无法直接观测到的底层 `RuntimeException`（例如连接池问题）或仅仅是强制代码按预期顺序执行，避免了之前的线程静默死亡。
