坚持和详细的日志反馈是解决问题的关键。

### 总结：双 IDE 协作开发中认证功能遇到的全部错误

我们这次排查的登录/注册功能，几乎涵盖了前后端分离开发中所有最常见的陷阱。以下是我们将遇到的所有问题及其解决过程：

#### 1. 认证拦截器错误 (Auth Filter Logic Error)

|**错误描述**|**出现症状**|**解决方案**|**负责方**|
|---|---|---|---|
|**误拦截登录/注册请求**|后端日志显示 AuthFilter 拦截了 `/register`，并返回 **`JWT_FAILURE_请求被拒绝...`** 错误。|在 `AuthFilter.java` 中，明确将 `/login` 和 `/register` (或 `/auth/login` 和 `/auth/register`) 加入 **豁免路径列表**，确保它们不进行 JWT 检查。|**后端 (IDEA)**|

#### 2. 数据库连接错误 (MySQL Connection Error)

|**错误描述**|**出现症状**|**解决方案**|**负责方**|
|---|---|---|---|
|**公钥检索错误**|`SQLNonTransientConnectionException: Public Key Retrieval is not allowed`|在 JDBC URL 中添加参数 `&allowPublicKeyRetrieval=true`。|**后端 (IDEA)**|
|**时区格式错误**|`DateTimeException: Invalid ID for region-based ZoneId...`|在 JDBC URL 中明确添加时区参数 `?serverTimezone=UTC`，并确保所有参数使用 `&` 正确分隔。|**后端 (IDEA)**|

#### 3. 前后端字段不匹配错误 (Field Mismatch Error)

|**错误描述**|**出现症状**|**解决方案**|**负责方**|
|---|---|---|---|
|**DAO 缺少 `phone` 字段**|DAO SQL 需要 4 个字段 (`phone`)，但前端只发送 3 个，导致数据库抛出 `NOT NULL` 异常 (500 错误)。|**统一字段要求：** 修改 `RegisterView.vue`，增加 `phone` 输入框并发送；同时在 `RegisterServlet` 中添加对所有必填字段（包括 `phone` 和 `email`）的非空校验。|**前后端 (VS Code & IDEA)**|

#### 4. URL 路径不匹配错误 (Path Mismatch Error)

|**错误描述**|**出现症状**|**解决方案**|**负责方**|
|---|---|---|---|
|**Servlet 映射冲突**|前端请求 `/auth/register`，但后端 Servlet 映射为 `/register`，或反之，导致 **404 Not Found**。|**统一路径：** 将 Servlet 映射修正为与前端请求路径一致 (`/auth/register`)，以遵循 API 文档结构。|**后端 (IDEA)**|

#### 5. 跨域预检错误 (CORS Preflight Error)

|**错误描述**|**出现症状**|**解决方案**|**负责方**|
|---|---|---|---|
|**OPTIONS 预检失败**|浏览器控制台显示 **`Access-Control-Allow-Origin` header is not present**，请求被阻止，前端显示 `Network Error`。|在 `AuthFilter.java` 的顶部：<br><br>  <br><br>a. 设置 `Access-Control-Allow-Origin` 等所有 CORS 头部。<br><br>  <br><br>b. 明确拦截并处理 `OPTIONS` 请求，直接返回 `200 OK`，不让它进入 JWT 检查或 Servlet 业务逻辑。|**后端 (IDEA)**|
