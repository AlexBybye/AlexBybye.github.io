> 这个适用于课程设计与论文等的结论亮点

值得注意的是，本次项目开发正值 2026 年人工智能辅助编程 Vibe Coding迎来爆发式普及的背景之下。在实际开发与工程落地过程中，我深刻体会到开发范式正在发生根本性转移——程序员的角色正逐步从底层的编码者Coder转变为宏观的代码审查者Reviewer与系统架构师。在拥有如 Claude Code 等先进工具的生态环境下，传统依靠记忆 API 和编写机械化代码的壁垒正在被迅速抹平，而技术人员的核心竞争力，已悄然转向对底层原理的精准理解、复杂业务的解构能力，以及对 AI 跨文件调用与数据流的审计与 Debug 能力。

由于这一技术浪潮对高校计算机专业学生的思维方式、工程流优化乃至未来的职业生态位都带来了巨大的冲击，**本次实验不仅是一次业务功能的技术实现，更是一次探索“AI 时代下如何产出高工程化质量代码”的实践尝试。关于在 Vibe Coding 生态下如何重塑工作流、定位核心壁垒以及应对深水区 Debug 的完整思考与方法论复盘，本人将在报告末尾的“总结与展望”章节中进行深度展开与补全。

首先，我想借着这个机会，表达下我对ai辅助编程的一些想法。
这次实验，个人总结锻炼的地方和感想主要有三点：
1：如何优化自己的vibe coding工作流包括接壤最新的vibe工具

2：如何能够在vibe coding生态环境下找到前端程序员甚至说开发岗位的生态位

3：如何Debug vibe coding 解决不了的任务

为什么我会这样说呢？本人目前入职了某互联网大厂的前端暑期实习，也优化了自己的vibe coding思路。从每个编程开始，到每个项目落地，我有以下三点感想。
如何产出可以经得起工程化的代码？其实就是上述的第一个问题。在我没优化自己工作流之前，我认为问题是如何解决代码健壮性以及性能优化，组件复用和迭代；但是在实际使用Claude code后，我认为问题转变成了如何做好代码的审核工作，因为它可以很轻松做到从宏观的角度去完成上述我之前旧的工作流暴露的问题。
所谓氛围编程时代，我们开发身份大多数情况从编码者变成了第一个Reviewer，甚至于如果舍得大手大脚花token，我们甚至可以配置一个agent帮我们做到这一点，包括多agent对抗式生成。
这些思路固然不只是我个人的思路，氛围编程时代，985大学生如果不能应用好最新工具，优势和普通学生再度缩小，我们不再是卷编码，而是卷调用。上面的思路，是我认识的几位富有想法的双非实习生、一线大厂在岗多年的老coder、甚至是来自于漫步在珠江新城时的一个学习优异的高二学生。很感慨，时代已然演变成我看不懂的模样，充满了魔幻现实主义的诡谲，仿佛大梦一场。也有可能是我站在了更高的平台，而再度给我的思想来了一次深刻的转变。
开发人员如何找到自己的生态位？我的第二个问题，是我第一个问题的诱因，一切的技术学习，都是为了将来有一技之长。传统开发古法编程，这可能和鲁迅笔下的孔乙己排出八枚大钱的炫耀没什么区别。这个问题我的答案是工具带来的生产力的提升，对技术人员提出了更高的要求：交代好自己的编码逻辑，人人都是架构师，如果是外行，可能只会说我要做一个红苹果落地的动画，然后多次修改prompt效果却不好。专业人员则可能说：帮我做一个flix弹性布局的组件动画，要求使用less语法，独立封装成一个文件。做一个红苹果从树上掉到地上的动画，苹果落地使用defineAnimationFrame提升性能......ai编程时代，开发的核心优势就是懂技术，有明确的提示词，问题拆解能力。我们悲观地说，以前想好逻辑去实现，可能有bug，可能有时间损耗；而现在ai工具犯得问题在我们精确提示词下就是核心业务逻辑没交代好，所以大脑一刻不得闲。
Debug vibe coding发生的问题又要怎么做？首先就是吃透ai编码逻辑，也就是错误潜在规避能力，包括跨文件调用以及各函数、数据流调用关系。所以我在遇到企业大项目一般都会每完成一个模块都习惯性跟一个解析文档。其次，就要通过编译器的溯源和查找，来定位错误位置，最后把核心错误位置和修改方案提供给AI，这样才能保证代码质量情况下高质量修复BUG。
AI时代的冲击，是从2025年12月开始的，在26年春招迎来了爆发。我的企业组长如是说。作为985大学的CS学生，我们要学会脱下自己学历的长衫，拥抱技术本真，才能保证自己的核心竞争力，我要感谢本学期所有开课的老师和我的实习公司。实习和本学期这些课设带给我的冲击是巨大的，以上均是有感而发，我也想和老师助教们分享，渴望得到斧正！
