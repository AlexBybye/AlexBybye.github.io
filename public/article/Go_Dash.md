### Day 1: 命令行 AI 提示词翻译器 (语法基础)

- **目标**：掌握 `var`, `func`, `struct`, `if/else`, `import`。
    
- **功能**：用户输入一段中文提示词，程序调用 API（或模拟）返回英文。
    
- **练习点**：
    
    - 定义 `Config` 结构体存储 API Key。
        
    - 使用 `flag` 包获取命令行参数。
        
    - 练习字符串拼接和基本逻辑。
        

### Day 2: 简易 AI 接口 Mock Server (工程化与接口)

- **目标**：掌握 `interface`, `type`, `package`, `error handling`。
    
- **功能**：定义一个 `LLMClient` 接口，分别实现 `OpenAI` 和 `Claude` 两个结构体。
    
- **练习点**：
    
    - **接口解耦**：让你的主程序只依赖接口，不依赖具体模型。
        
    - **错误处理**：模拟网络超时，返回 Go 风格的 `err`。
        
    - **JSON 处理**：练习序列化请求体。
        

### Day 3: 并发 AI 任务分发器 (并发原语 - 核心)

- **目标**：掌握 `go`, `chan`, `select`, `sync.WaitGroup`。
    
- **功能**：同时给 5 个不同的模型发请求，哪个最先返回就用哪个的结果（**竞速模式**）。
    
- **练习点**：
    
    - **Goroutine**：每个请求一个协程。
        
    - **Select**：监听多个 channel 的返回。
        
    - **超时控制**：用 `time.After` 防止程序死等。
        

### Day 4: 带中间件的 AI 流式转发网关 (Web 框架与 Context)

- **目标**：掌握 `context`, `defer`, `map`, `Gin 框架`。
    
- **功能**：用 Gin 写一个后端，接收前端请求，流式（Streaming）转发大模型响应。
    
- **练习点**：
    
    - **Context 传递**：如果客户端断开连接，如何立即通过 `ctx.Done()` 停止后端向 AI 厂商的请求。
        
    - **Middleware**：写一个统计 API 调用耗时的中间件。
        
    - **Defer**：确保连接关闭。
        

### Day 5: 向量数据库连接池 + 简单的 RAG 原型 (综合应用)

- **目标**：掌握 `make`, `range`, 指针，以及第三方库对接。
    
- **功能**：模拟一个简单的 RAG（检索增强生成）流程：用户提问 -> 查向量库（模拟）-> 拼接上下文 -> 调用 LLM。
    
- **练习点**：
    
    - **性能**：观察大量向量数据在大切片（Slice）中的处理。
        
    - **综合**：把前几天的并发、接口、错误处理全部融合在一起。

### 💡 如何利用 AI Coding 高效速成？

当你让 AI 写代码时，不要只看结果，要针对 Go 的特性追问它：

1. **“这段代码里的变量会发生‘内存逃逸’吗？”**（考察堆栈分配）
    
2. **“如果这个 Channel 忘记关闭，会导致协程泄漏吗？”**（考察并发安全）
    
3. **“为什么这里用指针传递结构体，而不是直接传递值？”**（考察性能与引用）

## Gemini 说

既然你的目标是 **Go 后端 + AI 方向**，面试官的考察重点会从单纯的语法转向**性能、高并发以及如何高效对接 AI 模型服务**。

在速成阶段，请务必吃透以下四个核心领域：

---

### 1. 高并发处理：不仅仅是 `go` 关键字

AI 业务（如大模型推理）通常是长耗时的。Go 的协程模型非常适合处理这种等待。

- **Context 控制**: 面试必考。AI 请求超时了怎么办？用户取消请求了怎么办？你需要熟练使用 `context.WithTimeout` 和 `context.WithCancel` 来优雅地终止正在进行的 API 调用或数据库查询。
    
- **Worker Pool (协程池)**: 别盲目开启无限个 Goroutine。在处理高频 AI 打标或向量化任务时，需要用协程池限制并发数，防止内存撑爆。
    
- **Channel 缓冲**: 了解无缓冲和有缓冲通道的区别，AI 流式输出（SSE/Streaming）通常靠 Channel 来分发数据块。
    

### 2. 性能优化：别让 Go 成为 AI 的瓶颈

AI 后端经常涉及大量的数据转换（如 JSON 处理、向量数组计算）。

- **序列化优化**: 标准库 `encoding/json` 反射太慢。速成时了解一下 `json-iterator` 或 `easyjson`。
    
- **内存逃逸分析**: AI 应用中频繁创建的大型向量数组如果逃逸到堆上，GC（垃圾回收）压力会剧增。学会用 `go build -gcflags="-m"` 查看逃逸情况。
    
- **cgo 机制**: 很多底层的 AI 推理库（如 TensorRT, llama.cpp）是 C++ 写的。面试可能会问你：Go 如何调用 C 代码？（了解 `cgo` 的成本和调用开销）。
    

### 3. AI 业务常用组件

- **流式输出 (Streaming)**: 理解如何用 Go 实现 Server-Sent Events (SSE)，这是 ChatGPT 式对话界面的标配。
    
- **向量数据库对接**: 熟悉如何使用 Go SDK 操作 Milvus、Pinecone 或 Weaviate。
    
- **Protobuf/gRPC**: AI 模型服务通常部署为独立的微服务，Go 后端通过 gRPC 与其通信比 HTTP/JSON 快得多。
    

### 4. 必会关键字深度面试题

针对你刚才列出的 25 个关键字，AI 方向面试常问：

- **`defer`**: 它的执行顺序（后进先出）？在循环里用 `defer` 会有什么问题？（容易堆栈溢出或延迟释放）。
    
- **`select`**: 如何用它实现超时控制？
    
- **`interface`**: 怎么判断一个变量是否实现了某个 AI 处理器接口？（断言与反射）。
